# 《桃李？逃离！》Implementation Plan

> 版本：2.0 · 日期：2026-11-26
> 状态：定稿。本文为唯一规则口径。

---

## 一、设计目标与范围

### 1.1 核心体验

在随机生成的教室中把握老师「板书 → 踱步 → 回头」的节奏间隙，通过移动与拉座椅向教室后门潜行。节奏判断失误会被老师抓住并触发英语答题，答错累积羞愧值，羞愧满则留堂失败。全程零失误抵达后门可达成无答题通关。

### 1.2 Demo 范围（本次要做）

- 随机生成教室地图 20×15（每局重排），含过道 / 书本 / 课桌 / 四类座椅 / 墙体 / 后门出口，保证起点到出口连通且至少两条可用路线
- 键盘移动 + 拉椅，动作锁与 1.5 拍 / 1 拍耗时
- 节拍时钟驱动的老师三板式状态机（板书 / 踱步 / 回头判定）
- 破损座椅异响（仅板书阶段、落地时按概率）
- 羞愧值 0–150 与递增惩罚曲线、统计与 5 种结局
- 四六级题库 + 四阶段闪回题库、10s 限时答题面板
- 双路线保证（一条绕行较安全、一条短路高危）
- 色块 + emoji + 文字占位的视觉反馈（本轮不接入正式美术资源）

### 1.3 明确不做

- 不做音效与背景音乐
- 不做移动端适配与触摸操作
- 不做后端、数据库、账号、排行榜、存档
- 不做逐帧美术动画（用色块 / emoji / 简易 transform 占位）
- 不做地图编辑器、关卡导入与地图存档（地图在运行时随机生成）

## 二、核心规则定稿

### 2.1 节拍与动作参数

| 参数 | 定稿值 | 备注 |
|------|--------|------|
| 1 拍 | 400ms | `BeatClock.beatMs`，集中可调 |
| 板书阶段 | 2–3 拍随机 | 整数拍 |
| 踱步阶段 | 3–4 拍随机 | 等概率 |
| 跨格移动 | 1.5 拍 | 动作结束才更新位置并判定 |
| 拉座椅 | 1 拍 | 不改变玩家位置 |
| 回头阶段 | 2–3 拍随机 | 持续危险窗口，窗口内移动即被抓 |
| 答题限时 | 10s（真实秒） | 独立于节拍，不受节拍冻结影响 |
| 异响概率 | 50% | 仅板书阶段 + 落地破损座椅 |
| 羞愧上限 | 150 | 全程钳制 0–150 |
| 闪回最低羞愧 | 30 | 低于 30 一律四六级题 |

### 2.2 格子类型与通行性

| 类型 | 通行 | 规则 | 占位表现 |
|------|------|------|----------|
| 过道 `aisle` | ✅ | 基础路线 | 深灰蓝底 |
| 书本/书包 `clutter` | ❌ | 遮挡，迫使绕行 | 棕底 + 📚 |
| 课桌本体 `desk` | ❌ | 台面不可穿 | 深棕底 + 🪑 |
| 空座椅·收起 `seatClosed` | ❌ | 必须先执行「拉座椅」转为 `seatOpen` | 暗蓝底 + 💺 + 虚线边框 |
| 空座椅·拉开 `seatOpen` | ✅ | 可正常进入 | 蓝色底 + 💺 |
| 破损座椅 `seatBroken` | ✅ | 高风险：板书阶段落地概率异响 | 暗红底 + 💺 + ❗ |
| 有人落座 `seatOccupied` | ❌ | 同学占座，视为障碍 | 灰底 + 👤 |
| 墙体 `wall` | ❌ | 地图边界 | 黑底 |
| 后门出口 `exit` | ✅ | 胜利目标，进入即通关 | 绿底 + 🚪 |
| 起点 `start` | ✅ | 出生位置 | 蓝底 + 🧑‍🎓 |

### 2.3 座椅交互

1. 只能对「相邻 + `seatClosed` + 无人」的座椅执行拉椅，耗时 1 拍。
2. 拉椅成功后该格变 `seatOpen`，玩家位置不变。
3. `seatOpen` / `seatOccupied` 不再响应拉椅。
4. `seatClosed` 不可直接进入，也不可穿越。

### 2.4 老师状态机（按拍推进）

```
【板书 board】2–3 拍
  ├─ 玩家可行动
  ├─ 落地破损座椅 → 50% 异响 → 强制切【踱步】并重掷拍数
  └─ 拍数耗尽 → 【踱步】

【踱步 pace】3–4 拍
  ├─ 玩家可行动
  └─ 拍数耗尽 → 【回头】

【回头 turn】2–3 拍（持续窗口，与板书同档随机）
  ├─ 进入瞬间：① 玩家已在出口 → 通关结算
  │             ② 羞愧 ≥150 → 留堂失败
  │             ③ 动作未落地 → 四六级题
  │             ④ 静止站在破损座椅 → 羞愧≥30 闪回题 / 否则四六级题
  ├─ 窗口内：玩家一旦移动（移动或拉椅）→ 立即四六级题
  ├─ 窗口内保持不动 → 安全，拍数耗尽回【板书】
  └─ 答题结束 → 回【踱步】（重掷 3–4 拍）
```

> 回头是持续危险窗口而非瞬时判定：进入时清算「动作未落地 / 破损座椅」，窗口内再靠玩家移动触发。

### 2.5 动作锁

1. 动作（移动 / 拉椅）执行期间屏蔽所有方向输入与新动作，不排队。
2. 动作结束后才重新接收输入。
3. 答题弹窗期间锁定全部输入，节拍时钟暂停。

### 2.6 羞愧值

- 范围 0–150，任何增减后钳制。
- 四六级：答对 −10；答错按 `failCount` 递增 +10 / +20 / +35 / +50（第 4 次及以后恒 +50）。
- 闪回：答对 −20；答错或超时 +10。
- `failCount` 只统计四六级答错，答对不清零，新开局归零；闪回不计入。
- 达到 150 → 留堂失败；若同一瞬间已到出口，以到门为优先。

### 2.7 闪回

- 触发：回头判定成立被抓 + 玩家静止且当前格为破损座椅 + 羞愧 ≥30。
- 按当前羞愧区间加权抽取回忆阶段：

| 羞愧区间 | 幼儿园 | 小学 | 初中 | 高中 |
|---|---:|---:|---:|---:|
| 30–59 | 60% | 25% | 10% | 5% |
| 60–89 | 5% | 60% | 25% | 10% |
| 90–119 | 10% | 5% | 60% | 25% |
| 120–149 | 5% | 10% | 25% | 60% |

- 同一次回头最多一次闪回；与四六级题互斥；结束后回到老师状态流转，不追加第二次判定。

### 2.8 结局判定

优先级：**① 抵达出口 → 逃离分支；② 羞愧 ≥150 → 留堂失败**。

| 结局 | 条件 |
|------|------|
| 节奏大师 | 逃离 且 总答题次数 = 0 |
| 英语大师 | 逃离 且 总答题 ≥1 且 全部答对 |
| 稳步前行 | 逃离 且 有对有错 且 答对率 ≥40% |
| 侥幸脱身 | 逃离 且 有对有错 且 答对率 <40% |
| 留堂失败 | 羞愧 ≥150 |

统计字段：总答题数、四六级对/错、闪回对/错、错题集合（单词 / 短语 / 语法点）。

### 3.1 随机地图生成规则

每局开始时重新生成一张 20×15 教室图（每格 48px，画布 960×768），起点固定左下角 (1, 13)，后门出口固定右上角 (18, 1)。

**骨架参数**

| 项 | 值 |
|---|---|
| 网格 | 20 列 × 15 行，tile 48px |
| 纵向通道 x | 1 / 5 / 9 / 13 / 18 |
| 横向通道 y | 1 / 6 / 10 / 13 |
| 座位区列块 | [2,4] [6,8] [10,12] [14,17] |
| 座位区行块 | [2,5] [7,9] [11,12] |
| 最短路径 | 约 29 步（≈17 秒） |

**生成流程**

1. 全图填充墙体，四边留 1 格边界墙。
2. 铺设基础过道：外圈环形过道 + 中部纵向 / 横向主通道，保证结构骨架永远连通。
3. 在过道之外的区块内成排放置座位区，按权重随机生成座椅状态：
   - 空座椅·拉开 35%
   - 空座椅·收起 30%
   - 破损座椅 15%
   - 有人落座 20%
4. 在座位区中随机点少量课桌本体（不可通行台面），占比约 10%。
5. 在过道上随机撒书本/书包，占比 8%，但**不放在过道交叉口**，避免堵死。
6. 起点 3 格范围内与出口 3 格范围内强制为过道，不放任何障碍。

**约束校验（生成后必须全部通过，否则重生成，最多 80 次）**

1. **免费通行路径**：仅使用 `aisle / seatOpen / seatBroken / exit / start` 的 BFS，起点必须能到达出口。
2. **双路线**：把上一步得到的最短路径中间格临时视为不可通行后再做一次 BFS，仍能到达出口。
3. **兜底**：80 次仍失败时，直接沿最短曼哈顿走廊打通一条过道并把沿途障碍改为 `aisle`，保证绝对可通关。

**设计取舍**

- 破损座椅只出现在座位区，且短线路径上的破损座椅密度高于绕行路径：生成后统计两条路线的破损座椅数，不满足则重掷，最多 4 次；仍不满足则接受当前图。
- 随机性只影响布局，不影响规则；同一局内地图不再变化。

### 3.2 视觉约定（v2 已落地）

美术与渲染规格以 `.trae/documents/pixel_art_design.md`（v2.3）为唯一口径，本轮已全部替换占位：

- 16×16 美术单位、×3 整数放大（48px/格），画布 960×768；`imageSmoothingEnabled = false`
- 视角约 20° 轻微立体俯视、平行投影，立物画顶面 / 南面 / 东面（明度 100 / 78 / 62%）
- 窗户、黑板、后门、讲台、吊灯、挂钟在顶部 48px 立面余量内绘制；窗内是草坡、湖、鸭子、长椅与看书同学
- 角色与道具改为绘制矢量像素 sprite，不再使用 emoji；HUD 保留文字
- 光照由 `LightingLayer` 五档驱动（色温 / 频闪 / 边缘红），不做整体压暗

## 四、实施阶段

### Phase 0：清理不再使用的实现
删除旧地图实现（10×8 随机格子）、旧毫秒老师计时器、鼠标点击移动、答错回退、覆盖层闪回，避免新旧逻辑并存。

### Phase 1：骨架与时间基准
`GameState` 状态机（含 RESULT）、`BeatClock`（唯一时间源 + 冻结）、`index.html` DOM 骨架、`main.css` 基础布局。

### Phase 2：地图与玩家动作
`MapData` + `MapManager`（随机生成、连通性与双路线校验、兜底打通、通行性、座椅两态、出口）、`Player`（1.5 拍移动、1 拍拉椅、动作锁、落地判定）、键盘输入。

### Phase 3：老师 AI 与回头判定
`TeacherAI`（板书 2–3 拍 / 踱步 3–4 拍 / 回头 2–3 拍持续窗口）、破损座椅异响、判定顺序按 2.4。

### Phase 4：羞愧值与统计
`ShameTracker`（0–150、递增曲线、闪回区间权重）、`ResultManager`（统计 + 错题集合）。

### Phase 5：题库与答题面板
`QuizBank` + `FlashbackBank`、`QuizManager`（三栏面板、10s 倒计时、超时判错、对错反馈）、四六级 / 闪回两套视觉区分。

### Phase 6：结局与流程闭环
5 种结局判定与展示、开始 / 再来一次 / 重置（清空所有队列与统计）。

### Phase 7：渲染与反馈
地图分层渲染、老师三态动画占位、羞愧条、压力视觉（边缘压暗 / 灰雾 / 抖动）、状态文字提示。

### Phase 8：验证与调优
按 checklist 全量走查 + 调整节拍时长、异响概率、题库难度。

## 五、验证要点

1. 节拍时钟冻结：答题面板打开时板书/踱步拍数不推进；关闭后从冻结点继续。
2. 动作锁：移动 1.5 拍期间无法再次输入；落地后位置与判定同步更新。
3. 被抓判定：仅在动作未落地或静止站破损座椅时成立；移动完整落地后回头安全。
4. 全程不答题也可通关（节奏大师）。
5. 抵达出口优先于羞愧 150。
6. 闪回仅在「破损座椅静止 + 羞愧≥30 + 被抓」时出现，且不与四六级题同现。
7. 拉椅：收起座椅不可直接进入；拉开后 1 拍内完成、位置不变。
8. 异响仅板书阶段触发，踱步阶段不重复触发，且不打断玩家动作。
9. 结局与统计：4 种逃离分支 + 1 种失败，错题知识点正确汇总。
10. 新局重置：羞愧、failCount、统计、错题、地图座椅状态、老师状态全部归零。
11. 随机地图：每局重新生成且始终可通关；起点与出口各 3 格范围内无障碍；至少两条路线。

## 六、调优项与风险

### 6.1 调优项

| 项 | 当前值 | 调整方向 |
|---|---|---|
| 节拍时长 | 400ms | 手感偏快则上调，只改 `BeatClock.beatMs` |
| 板书拍数 | 2–3 | 玩家反应不过来则扩到 3–4 |
| 踱步拍数 | 3–4 | 压力不足可加入 5 拍长踱步 |
| 回头拍数 | 2–3 | 太长会让玩家无路可走，建议不超过 4 |
| 异响概率 | 50% | 出现太频繁则降到 30% |
| 闪回触发面 | 破损座椅静止 + 羞愧≥30 | 出现太少可放宽为「任何被抓 + 羞愧≥30 按 50% 概率转闪回」 |
| 答题后回踱步 | 立即 | 节奏过紧可改为回板书并给 2 拍缓冲 |

### 6.2 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 拍事件在多拍跨越时丢失 | 老师少走一拍、判定错位 | 用循环补齐每一拍 |
| 动作进度与拍时钟不同步 | 落地时刻与回头判定错位 | 两者共用同一 `deltaMs` 累加 |
| 随机地图偶发无解或路线单一 | 玩家无法通关 | 生成后 BFS 双重校验 + 最多 50 次重生成 + 兜底打通走廊 |
| ES Module 需 HTTP server | 直接双击打不开 | 保留 `start.cmd` + `server.cjs`，开始页标注启动方式 |
